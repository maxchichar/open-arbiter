## 1. Versioned pre-push hook (`.githooks/pre-push`)

Enabled with the pre-commit hook by `npm install` (`core.hooksPath .githooks`). A push goes through only when:

1. every pushed ref is HEAD (tags are peeled to their commit), because `npm test` can only vouch for the checked-out commit;
2. the working tree is clean, untracked files included, so what is tested is what is pushed;
3. `node scripts/secret-scan.mjs --history` is clean;
4. `npm test` passes on HEAD. When it fails, the hook shows the last 80 lines and names the opt-out.

`OPEN_ARBITER_ALLOW_RED_PUSH=1` (exactly `1`; `true`, `yes`, `0` and empty don't count) skips **only** step 4 and prints `pre-push: BYPASSED: npm test was NOT run on <sha>`. A dirty tree or a secret in history is refused even with the opt-out. Deleting a remote branch runs no checks. `--no-verify` remains possible in git itself; CLAUDE.md forbids it.

## 2. `/health` cached per Worker instance for 10 s

`arbiter/src/health.js` keeps one entry per database binding per instance: `{at, checks}`, where `checks` is the in-flight or finished run. Concurrent requests share one run. After `HEALTH_TTL_MS` (10 000 ms) the next request runs the checks again. **Failures are cached too**, so a burst against a broken deployment also costs at most 3 statements, and a fix shows within 10 s. Each response is built fresh, with its own `request_id`. A new field, `checked_at`, says when the checks ran. An unexpected rejection drops the entry. `cache-control: no-store` is unchanged: clients and the edge never cache it.
