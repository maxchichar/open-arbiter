# P1.6: `GET /health`: evidence (2026-11-27)

Plan: [`../plan.md`](../plan.md) § P1.6. Local only: nothing written to Cloudflare. The `wrangler deploy --dry-run` runs only build.

## Research

- **Version metadata binding** (https://developers.cloudflare.com/workers/runtime-apis/bindings/version-metadata/, dateModified 2026-07-03): `[version_metadata] binding = "CF_VERSION_METADATA"`, with fields `id`, `tag`, `timestamp`. The page says nothing about plan availability. Checked locally with wrangler 4.166.0: the binding is **not inherited** by `[env.X]` (the config reader returns `undefined`), so each environment declares it. Under `wrangler dev` it gives a random `id` and an empty `tag`. `wrangler deploy --help` lists `--tag`, `--message` and `--var`. Free-plan behaviour gets confirmed on the first staging deploy (P1.4b: `/health` `version.worker` must equal `wrangler deployments list`).
- **Owner, 2026-11-27:** the P1.8 item (AC-8.5) is added to the plan: on staging, check what Workers Logs stores for a request carrying a planted token and an IP-style header.

## Red first

`p1.6-red-tests.txt` (exit 1): 19 of 41 fail. There is no `/health`, the log `version` is a string, the deploy passes no commit, there is no `version_metadata`, and the vendor-page line and runbook section are missing. One failure is a **real defect**: an unparseable `ARBITER_SIGNING_JWK` crashed every route as `internal`, because the Worker ran `JSON.parse` on each request.

## What changed

- `arbiter/src/health.js`, `GET /health`:
  - **Healthy:** 200 `{ok, version: {worker, tag, mechanism, git}, db, key: {loaded, kid, source}, migrations: {latest, applied}, schema}`.
  - **Misconfigured:** 503 with a registry code and every check in the body: `db_unavailable`, `schema_outdated` (no migrations table), `migrations_pending`, `key_missing`, `key_invalid`, `key_dev_in_deployed_env` (`DEV=1` in staging or production).
  - **Cost:** at most 3 statements (`SELECT 1`, `d1_migrations`, and the dev key's id in local dev only). No business table, never a write, only the `kid`, `cache-control: no-store`. It runs before the Arbiter is built, so a bad key secret is reported, not crashed on.
- Six `/health` codes added to `errors.js`, plus `details` (value-free body fields). The README table is regenerated from the registry.
- `signingJwkOf`: a key secret that isn't a private P-256 JWK now gives `misconfigured` (`reason: signing_key_invalid`) on every route, instead of `internal`.
- **Log line `version` is now `{worker, mechanism, git}`**. `worker` is the version id from the binding (`local` without it), and `git` is `GIT_SHA` (`unknown` without it).
- `deploy.mjs` passes `--var GIT_SHA:<commit>` and `--tag <first 12>`, with `-dirty` added when the tree has changes. Git is read only after the arguments are valid.
- `wrangler.toml`: `[version_metadata]` at the top level and in each environment.
- Seller console (`/vendor`): a status line from `/health` ("Arbiter healthy · signing key <kid> · database at <migration>", or the error code). Runbook `## After a deploy`: step 1 is `/health`, with what to do for each code. `GET /` lists `health`.
