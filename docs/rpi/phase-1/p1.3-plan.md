## Target behaviour

One workflow, `.github/workflows/ci.yml`:
- Triggers: `push` (all branches) and `pull_request`. **Never `pull_request_target`.**
- Top-level `permissions: contents: read`.
- No `secrets.*` and no `environment:` anywhere.
- `concurrency` cancels superseded runs.
- Every job has a `timeout-minutes`.
- Every checkout uses `persist-credentials: false`.

| Job | Steps | Covers |
| --- | --- | --- |
| `unit` | checkout (`fetch-depth: 0`) → setup-node 24 (npm cache) → `npm ci` → `npm test` → `node scripts/secret-scan.mjs` (whole tree) → `npm run test:m2` → `node --test` on the CI-guard tests | AC-3.1, AC-3.4, AC-3.5, AC-3.6 |
| `worker` | checkout → node → `npm ci` → `npm run test:worker` → `npm run test:migrations-d1` (local wrangler; `WRANGLER_SEND_METRICS=false`, `CI=1`) | AC-3.1, AC-3.6 |
| `network-and-browser` | checkout → node → python → clone `agentic-web` at **`d67755e…`**, then check `git rev-parse HEAD` equals the pin → `build_network.mjs` validation → start the local arbiter, seed, site and fake LLM → `pip install playwright==<pinned>` and `playwright install --with-deps chromium` → `browser_check.py` (0 CSP violations) → upload the screenshots (7-day retention) | AC-3.1 (copy, CSP, config), CLAUDE.md invariant 13 |

## Acceptance criteria for this slice

- **C1.** Every job above is green on the `phase-1` push and on a PR to `main`. Evidence: run URLs plus the job logs saved with `save-output` through `gh run view --log`.
- **C2 (red first).** Each guard is shown failing on purpose, on a throwaway branch that's then deleted:
  - (a) a failing unit test makes `unit` red;
  - (b) a staged fake key makes the secret scan red;
  - (c) an M2-incompatible migration makes `test:m2` red;
  - (d) a CSP violation (`CSP_DROP_STYLE_HASH=1`) makes the browser job red.
- **C3. AC-3.4 test** (`arbiter/test/ci-workflow.test.mjs`, in `npm test`, no new dependency, text and structure checks). The test fails if any file in `.github/workflows/`:
  - contains `production` in a wrangler, deploy or migrations command, `--env production`, or `--confirm-production`;
  - runs `migrations apply … --remote`, or uses `wrangler-action`;
  - references `secrets.` (except `GITHUB_TOKEN`, which is not used yet), or uses `pull_request_target`;
  - is missing `permissions: contents: read`;
  - uses an action that isn't pinned to a 40-character SHA;
  - checks out without `persist-credentials: false`.

  Fixture workflows show each of these being rejected.
- **C4. AC-3.5 M3 guard.** `scripts/m3-guard.mjs` plus tests:
  - It compares `MECHANISM.version` at HEAD with the merge base on `main` (`fetch-depth: 0` makes this possible).
  - If the version changed, it fails when any workflow or `arbiter/scripts/deploy.mjs` contains `versions deploy` or `--percentage` / `gradual`.
  - Today nothing uses them, so it passes. Fixtures show it failing (version changed plus a `versions deploy --percentage 10` step) and passing (version changed, `wrangler deploy` only; or version unchanged).
  - P1.4 inherits it when deploy jobs arrive.
- **C5.** The workflow runs `test:m2` against every `v*` tag. A tag missing in CI (shallow clone) fails loudly instead of checking nothing: `m2-check` exits non-zero when it finds no tags, tested.
- **C6.** Runtime budget: the whole workflow finishes in under 15 minutes. Times recorded from the first green run.
